# Print Finder — handover

A static site (GitHub Pages) that searches open-access museum collections and shows every public-domain image that prints at the smallest size of the chosen size system or larger, at the chosen DPI (default 200). Size systems: A sizes (A4 … 4A0), US inches (8×10 … 24×36), frame sizes in cm (18×24 … 70×100) and square (20×20 … 100×100 cm). Each card shows the largest size the image can print, directly under the thumbnail.

## Files
- `index.html` — the whole app (HTML/CSS/JS, no build step). Calls museum APIs directly from the browser.
- `nga-index-v2.json` — pre-built index of ~59k National Gallery of Art (Washington) open-access images (long side ≥ 2,480 px), built from github.com/NationalGalleryOfArt/opendata (`published_images.csv` + `objects.csv`). Columnar: `{format, n, id[] (uuid without dashes), w[], h[], title[], artists[] + artist[] (index into artists), date[], y0[], y1[], cls (one string, a letter per row: p/d/r/f/o), media[] + medium[] (index), kw[], oid[]}`. 12.7 MB (4.1 MB gzipped), about 3× faster to parse than the old row format. Only fetched when NGA is searched.

## Sources (`adapters` in `index.html`; each returns `{items, more}`, `st` = that source's paging state)
Every source except Wikimedia (`vetted:false`) re-checks each result's licence on our side; never rely on a search filter alone. Each item also carries `rights` = a link to its rights statement (the CC0 deed for sources that are CC0 by policy; the record's own creativecommons.org / rightsstatements.org link otherwise; none for LoC and Mia).

## How the app works
- **Search state:** `run()` stores the submitted search in `searched`. Rendering and fetching use `cur()` = that search + the live dpi, layout and licence settings. Typing in the form changes nothing until Search is pressed. Each search is a history entry (Back/Forward re-run it).
- **Fetching:** each source pages independently (`sourceLoop`, up to 4 rounds per top-up). Infinite scroll: 48 cards at a time; `maybeMore()` runs after every render and when `#more` comes within `NEAR` px. It only fetches again if the previous batch added visible results (`lastFetchAt`), otherwise it shows a "Search deeper" button — heavy filters can't make it fetch forever.
- **Ordering:** default **Best match** = titles containing every keyword first, then each source's own relevance order (`srank`, so sources interleave). Cards the viewer has scrolled past are pinned (`view.order`) so nothing jumps while scrolling. `resetView()` (any sort/filter/setting change) starts again from the top.
- **Print maths:** `SYSTEMS` lists each size system (sizes in mm, chips for the size filter). `fit()` grades an item against every size of the chosen system ("contain" dpi = max(long/paperLong, short/paperShort), "cover" = min; `crop` = how much a fill would cut off). `fitOf()` memoises it per dpi/layout/system in a WeakMap — results are re-filtered and sorted on every redraw (10k results ≈65 ms).
- **Medium "Poster / graphic design"** (`graphic`): Met, Getty, LoC and Wellcome use their own poster category; every other source searches with the word "poster" added (`srcOpts`), and `keep()` then only keeps items whose title or medium says poster / affiche / Plakat / broadside / advert etc. (not poster paint, not photographs of posters).
- **Filters after searching:** source pills, shape, size chips (from the chosen system, e.g. A3+ … A0+ or 16×20 in+), **Artworks only** (`JUNK` regex on each museum's object type / medium text, never titles — "Vase of Flowers" is usually a picture), licence setting. Status counts are after all filters except the source pills.
- **Cards** are cached by id in `cardCache` (cleared on dpi/layout/size-system change) and the grid is appended to rather than rebuilt while scrolling, so images don't reload and keyboard focus stays put. Board stars are re-synced on every render.
- **Licence badges** come from each item's own licence (`licLabel`): "CC0" only when it really is CC0, otherwise "Public domain" / "No known restrictions".
- **Boards:** `pf_boards` in localStorage = [{id,name,items:[snapshot]}] (old `pf_shortlist` migrates into "Shortlist"). ☆ Save on a card / "Save to board…" in the detail view opens `boardPicker()`. Boards dialog: switch, create, rename (inline), delete, CSV (UTF-8 BOM, formula-safe), Backup/Import (validated and cleaned through `snap()` before anything merges; links must be http(s)). Other tabs pick up changes via the `storage` event. Browser-only — no sync between devices.
- **Licence record:** each saved item keeps `licence`, `rights` and `saved` (the day it was saved = the day the licence was checked). Boards dialog → "Licence record" opens a printable page (blob URL, new tab; downloads it as .html if pop-ups are blocked) with source, licence, rights link, museum page, file link, pixels and date per image (the viewer's local date). Wikimedia items carry the "check the file page" warning there too. Items saved before this existed show "not recorded". The CSV has the same fields.
- **Print-ready file** (detail view → "Make print file…", only for items with `iiif`: NGA, Rijks, Getty, Yale ×2, SMK, AIC, Wellcome, LoC). A file with the sheet's exact shape, in one of two layouts (defaulting to the search's Layout setting): **Whole image, with margins** (the whole picture centred on white paper) or **Fill the sheet (crop)** (a crop frame to drag / arrow-key, "Crop tighter"). Size, orientation (not for square sizes), and resolution ≤300 / ≤400 dpi / everything. `plan()` works out the crop on the museum's own pixel grid (`info.json`), the picture and file sizes and the real dpi; the size list and default size use it too, so the ✓/✗ shown is what you get.
  - **One request** when no margins are needed and the server's limits allow it (`iiifLimits`: stated `maxWidth/maxHeight/maxArea`, plus NGA's unstated 4,096 px a side, `NGA_ONE`): the museum's own JPEG, untouched. Size `max` on IIIF 3 servers, `full` on IIIF 2 (Rijks rejects `full`, LoC rejects `max`). The returned size is checked (`sofSize`); a server that quietly sends another size falls through to pieces.
  - **Canvas** (`stitch`) otherwise: pieces ≤4,096 px at the final scale (8 px overlap when the server scales, so no seams), joined on one canvas with white margins if asked, saved as JPEG quality 0.95. `CANVAS_MAX` is each browser's canvas limit (iPhone/iPad ≈16.7 MP, and Android kept to the same for memory; Firefox 125 MP; Chrome/Edge/Mac Safari 268 MP); `plan()` keeps canvas-built files under it and says so, and `canvasFor()` probes at download time and shrinks further if the browser refuses.
  - Some LoC masters can't be scaled at all (HTTP 500 for any size but `full`): the tool then fetches every pixel and says so.
  - `jpegWithDpi` writes the real dpi into the JFIF header (and drops any Exif block, whose own 72 dpi some programs prefer), working on the first bytes of a Blob so big files aren't copied. If saving fails (no CORS / server error) it links to the biggest single file the server sends for that crop.
- **Wall preview** ("See it on a wall"): the print framed above a 210 cm sofa, everything to scale in cm; size, frame (black/white/oak/none), white mount, five wall colours. Uses the preview image, not the full file.
- **Similar** (metadata only, no image matching): card button = longest title word + same medium; detail view chips = each title word (same medium, ±30 yrs), "by <surname>", "any <medium> <years>".
- **Safety:** museum text is only ever inserted escaped (`esc`) or parsed inertly (`strip` uses DOMParser); links pass `safeUrl` (http/https only); pixel sizes are coerced to numbers on arrival.

## Known gaps / ideas
- **Settings → Test all sources** runs one small live search per source from the viewer's browser. Use it first when anything breaks.
- Not verifiable from the cloud sandbox: AIC images (blocked everywhere, see the AIC row), Wellcome full-size images, Wikimedia (intermittent 429), Smithsonian (DEMO_KEY quota). Sandbox allowlist needs `*.collections.yale.edu`, `*.loc.gov`, `*.wellcomecollection.org`, `*.artsmia.org` plus the museum API hosts.
- Not added: NYPL (API sends no CORS headers — unusable from a browser). Candidates needing a free key: Harvard Art Museums, Paris Musées, Te Papa.
- **Openverse checked and not added (Oct 2026).** Its public-domain results are mostly sources we already search; the rest are small (Flickr copies of BHL/NASA at 1,024 px, rawpixel previews at 1,024 px) or not public domain (Brooklyn is CC BY, Science Museum BY-NC-SA, Finnish collections BY). Anonymous use is limited to 20 requests/min and 200/day per visitor.
- **"Search every public-domain collection"** can't be done by calling each museum live from the browser (each source added makes searches slower and the API limits bite). The real step is a self-built index: a nightly job (e.g. GitHub Actions) that harvests the museums' bulk open-data dumps into one database (e.g. Cloudflare D1 + a Worker), searched in one request. Not started.
- The print file needs a IIIF image server, so it isn't offered for the Met, Cleveland, Smithsonian, Mia, Europeana or Wikimedia — their download link gives the whole image instead.
